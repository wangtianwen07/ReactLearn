# 90 验收清单（Checklists）：把“学会”变成“可交付”

> 用 checklist 对抗遗忘与返工：每阶段都有“必须达标”的验收点。

使用方式：

- 每完成一个阶段，把对应清单勾完
- 可以把清单复制到 PR 模板/迭代验收文档

---

## A. 通用工程清单（每个阶段都适用）

### A1. 代码与结构

- [ ] 目录结构能解释：每一层按“变更原因”划分
- [ ] 模块边界清晰：页面/领域/通用组件不过度耦合
- [ ] 不滥用 `any`，关键数据结构有 TS 类型
- [ ] 关键逻辑有注释/README（不是对代码逐行解释，而是解释“为什么”）

### A2. Git 与协作

- [ ] 提交信息符合 Conventional Commits
- [ ] PR 描述包含：变更点/影响面/测试点/截图/回滚
- [ ] 重要决定写入 `92-tech-stack-decisions.md`（ADR）

### A3. 安全与合规（ToB 必备口径）

- [ ] 不把敏感信息写入前端代码（密钥、真实账号）
- [ ] Token 存储策略明确（localStorage/cookie）并说明风险
- [ ] 错误信息对用户友好，对排错可追溯（traceId）

---

## B. 第 1 月验收（Web/TS + 静态原型）

- [ ] 能用 DevTools 定位接口失败原因（至少 1 个案例笔记）
- [ ] 能解释事件循环与常见竞态（至少 1 个案例）
- [ ] TS strict 开启（或说明为何暂不开启）
- [ ] 静态原型包含：布局 + 列表 + 查询表单 + 详情页
- [ ] 具备统一的空态/加载态/错误态占位

---

## C. 第 2 月验收（React SPA 主线）

### C1. 路由与布局

- [ ] 多层路由 + 布局路由
- [ ] 路由懒加载（chunk 拆分可见）
- [ ] 403/404 页面占位

### C2. 请求层

- [ ] 统一 `apiClient`：baseURL、超时、header
- [ ] 统一错误对象（含业务码、traceId）
- [ ] 401 行为明确：跳转/刷新 token（占位即可）

### C3. 状态分层

- [ ] 服务端状态用 TanStack Query（缓存/失效）
- [ ] 本地 UI 状态用 Zustand
- [ ] 筛选条件可落 URL（可分享、可回放）

### C4. 表单

- [ ] 表单校验（RHF + Zod），提示一致
- [ ] 防重复提交（loading/禁用）

---

## D. 第 3 月验收（工程化与质量）

### D1. 规范

- [ ] ESLint/Prettier/Stylelint 生效
- [ ] Husky + lint-staged 生效
- [ ] commitlint 生效

### D2. 测试

- [ ] `pnpm test` 可运行
- [ ] 关键模块有单测（请求层/权限工具/表单）
- [ ] E2E 至少覆盖 1 条关键路径

### D3. CI

- [ ] CI 包含 lint/test/build
- [ ] CI 失败会阻断合并（至少说明流程）

### D4. 可观测性

- [ ] ErrorBoundary
- [ ] `reportError/reportEvent` 占位（说明将接入何种平台：Sentry/自研）
- [ ] sourcemap 策略说明（生产是否上传、如何定位）

---

## E. 第 4 月验收（RBAC 三层权限）

### E1. 菜单/路由

- [ ] 菜单与路由权限一致（不可见/不可达）
- [ ] 未授权路由展示 403

### E2. 按钮/操作

- [ ] actionKey 命名规则固定
- [ ] `<Can/>` 或 `useCan()` 生效

### E3. 数据权限

- [ ] 行级权限至少 2 种 scope（ALL/DEPT/SELF 等）
- [ ] 字段级策略有示例（脱敏/不可编辑/不可见）

### E4. 会话

- [ ] token 过期处理策略清晰
- [ ] 并发刷新策略说明（最好有状态机图）

---

## F. 第 5 月验收（微前端 qiankun）

- [ ] 基座 + 至少 2 子应用可独立开发与联跑
- [ ] 基座统一登录态与权限，子应用消费
- [ ] 子应用可独立发布（至少文档说明与配置方案）
- [ ] 共享包边界清晰（types/auth/api-client/utils）
- [ ] 跨子应用关键路径 E2E 至少 1 条

---

## G. 第 6 月验收（Next.js 辅线 + 总交付）

- [ ] Next.js 模块完成（帮助中心/文档站/状态页择一）
- [ ] 与 SPA 共存方案说明（反向代理路由优先）
- [ ] Capstone 交付文档完整：
  - [ ] 架构图
  - [ ] 权限模型
  - [ ] 微前端域图
  - [ ] 发布/回滚手册
  - [ ] 演示脚本与演示账号权限矩阵

---

## H. 发布前检查清单（适合 ToB 中后台）

- [ ] 环境变量与配置已核对（API baseURL、sourcemap、监控 DSN）
- [ ] 静态资源缓存策略明确（hash 文件强缓存）
- [ ] 接口错误兜底：网络断开、超时、后端 500
- [ ] 关键路径自测：登录、权限、核心业务流程
- [ ] 回滚方案明确（上一版本制品可用）

---

## I. 性能与体验清单（不要等线上卡了再改）

- [ ] 路由级懒加载
- [ ] 长列表虚拟滚动（若有 1000+ 行）
- [ ] 防抖/节流用于高频输入与滚动监听
- [ ] 页面加载态与骨架屏（必要时）
- [ ] 图片与图表按需加载

---

## J. 你作为“后端转前端”的加分点清单

- [ ] 接口契约写得清楚（分页/排序/错误码/traceId）
- [ ] 鉴权与会话逻辑稳健（并发刷新/踢下线/多端登录）
- [ ] 权限三层一致（体验 + 安全）
- [ ] 可观测性口径清晰（错误定位不靠猜）
