# 03 第 3 月：工程化与质量体系（让项目能协作、能上线、可回滚）

> 本月定位：把“能跑的项目”升级为“团队可协作、可测试、可发布”的工程。

- 时间预算：4 周 × 10h/周
- 本月产出物（必须）：
  1. 规范体系：ESLint/Prettier/Stylelint + Git hooks + commitlint
  2. 测试体系：Vitest + RTL + MSW（单测/组件测）+ Playwright（E2E）最小可用
  3. CI：至少包含 lint/test/build
  4. 可观测性基础：错误边界、日志上报占位、Sourcemap 策略说明

---

## 3.1 企业级“工程化”你要对齐哪些维度

1. **一致性**：格式/规则统一，不靠人肉记忆
2. **可回滚**：变更可追溯、版本可定位
3. **可测试**：关键逻辑有自动化保护
4. **可观测**：线上问题可定位（traceId + sourcemap + 错误上报）
5. **可控成本**：构建时间、依赖膨胀、bundle 体积可量化

---

## 3.2 每周安排（10h/周）

### Week 1：规范与提交质量（把“团队门槛”设起来）

**学习重点（3h）：**

- ESLint/Prettier 的职责分离
- Conventional Commits / 变更日志的意义

**编码练习（5h）：**

- 接入并统一：
  - ESLint（含 React/TS 推荐规则）
  - Prettier
  - Stylelint（如使用 Less/CSS）
- Git hooks（Husky + lint-staged）：
  - 提交前自动 lint/format
- commitlint：提交信息不合规直接拒绝

**复盘（2h）：**

- 写“哪些规则必须强制，哪些可以警告”的团队约定

**验收：**

- 新人 clone 仓库后，提交不合规范会被自动拦截

---

### Week 2：单测/组件测（先保护最容易坏的地方）

**学习重点（3h）：**

- Vitest 基本
- React Testing Library：以用户行为测试而不是测实现

**编码练习（5h）：**

- 为以下模块补最小单测：
  - 请求层错误转换（error normalize）
  - 权限工具函数（先占位，4 月会增强）
  - 一个典型表单组件（校验、提交）
- 引入 MSW 用于测试环境 mock API

**复盘（2h）：**

- 写“哪些不测”：纯 UI 样式、第三方组件内部实现

**验收：**

- `pnpm test` 可稳定运行；失败能定位原因

---

### Week 3：E2E（关键路径自动化）

**学习重点（3h）：**

- Playwright（或 Cypress）测试思路：只测关键路径

**编码练习（5h）：**

- 写 2~3 条关键路径 E2E：
  - 登录 → 进入用户列表 → 搜索 → 打开详情
  - 新增用户 → 列表刷新
- 固化测试数据策略（使用 MSW 或测试环境后端）

**复盘（2h）：**

- 写“为何 E2E 不能覆盖一切”的说明（成本/脆弱性）

**验收：**

- CI 上能跑 E2E（可使用 headless）

---

### Week 4：CI/CD 雏形 + 可观测性与性能基线

**学习重点（3h）：**

- CI 基本：lint/test/build
- sourcemap 与错误定位
- 性能指标基线：首屏、交互延迟、bundle 体积

**编码练习（5h）：**

- CI（按你未来企业环境适配，先写“最小版本”）：
  - 安装依赖
  - lint
  - test
  - build
- 可观测性占位：
  - React ErrorBoundary
  - 统一日志接口（`reportError`, `reportEvent`）
- 性能基线：
  - 记录当前构建产物大小
  - 路由懒加载策略说明

**复盘（2h）：**

- 写“第 3 月工程化总结”：你建立了哪些护栏？

**验收：**

- 新 PR 必须过 CI；线上错误可通过 sourcemap 定位到源码（策略说明）

---

## 3.3 企业级 PR 模板（建议写入 checklist）

每次提交/PR 至少包含：

- 变更点（What）
- 原因（Why）
- 影响范围（Impact）
- 测试点（How to test）
- 截图/录屏（UI 变更必填）
- 回滚策略（Rollback）

---

## 3.4 本月对后端同学最友好的产物

- 接口错误码分层文档（前端怎么展示、怎么兜底）
- `traceId` 透传与展示策略（出问题能对齐后端日志）
