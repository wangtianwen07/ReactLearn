# 实战项目训练营：SaaS Admin Platform（ToB 中后台样板工程）

> 这是贯穿 6 个月的“真实项目实践”。你学习的每个知识点都必须在这个项目里落地为可演示功能。

---

## 1. 项目目标（你最终要交付什么）

交付一个可演示的企业级 ToB 中后台：

- 多角色登录
- 组织/用户/角色/权限（IAM 域）闭环
- 工单域（Ticket）闭环
- 数据看板（Dashboard）
- RBAC 三层权限：菜单/按钮/数据
- 微前端：按业务域拆分子应用并独立交付（qiankun）
- 工程化：规范、测试、CI、发布/回滚说明

---

## 2. 业务范围（固定范围，避免无限扩展）

### 2.1 域划分（微前端按业务域拆分）

- Shell（基座）：会话、权限初始化、导航、公共依赖、可观测
- IAM 域：组织、用户、角色、权限、菜单、资源
- Ticket 域：工单流程
- Dashboard 域（可选）：指标看板

### 2.2 角色设计（至少 3 种，用于演示权限差异）

- `SUPER_ADMIN`：全权限
- `ORG_ADMIN`：本组织管理权限（含用户管理、工单管理）
- `AGENT`：仅处理工单（不可管理用户/角色）

---

## 3. 功能清单（建议按页面/接口验收）

### 3.1 通用（基座）

- 登录/退出
- 个人信息与修改密码（可选）
- 全局布局（侧边菜单、顶部栏、面包屑）
- 全局异常与兜底：403/404/500、网络异常提示

### 3.2 IAM 域（最核心）

- 组织管理：组织树、部门新增/编辑
- 用户管理：列表/搜索/新增/编辑/禁用
- 角色管理：列表/新增/编辑
- 授权：
  - 角色授权菜单（route/menu）
  - 角色授权操作（action/button）
  - 角色授权数据范围（data scope）
- 菜单管理：菜单树配置（可选，演示用）
- 资源管理：API 资源（可选，偏治理）

### 3.3 Ticket 域（业务闭环）

- 工单列表：筛选、分页、状态流转
- 工单详情：
  - 基本信息
  - 处理记录（时间轴）
  - 操作：认领、转派、处理、关闭
- 审计：关键操作记录（至少前端埋点 + 后端日志口径）

### 3.4 Dashboard 域（可选但很加分）

- 指标卡：今日新增工单、待处理工单等
- 趋势图：最近 7 天
- 明细钻取：点击指标 → 跳转列表并带筛选条件（URL 状态）

---

## 4. RBAC 三层权限在项目中的验收方式

### 4.1 菜单/路由权限

- 验收：不同角色登录后侧边栏菜单不同；手动输入 URL 也无法进入

### 4.2 按钮权限

- 验收：无权限账号看不到/点不了“新增用户/删除/导出/授权”等按钮

### 4.3 数据权限（行级 + 字段级）

- 行级：
  - ORG_ADMIN 只能看到本组织数据
  - SUPER_ADMIN 可看全量
- 字段级（至少 1 个字段示例）：
  - 电话/邮箱脱敏（或仅管理员可见）

> 注意：数据权限必须以后端为准，前端只做一致性与体验。

---

## 5. 非功能需求（企业级必须考虑）

### 5.1 性能

- 列表页支持 1000+ 行时不卡（虚拟滚动或分页）
- 路由级懒加载
- 图表按需加载

### 5.2 稳定性

- 请求层统一错误处理
- token 过期与刷新策略（并发刷新）
- 全局 ErrorBoundary

### 5.3 可观测性

- 统一上报：页面错误、请求错误、关键操作事件
- traceId 展示与透传（与后端日志对齐）

### 5.4 可维护性

- 模块边界清晰
- 关键模块有单测与 E2E
- 文档齐全（架构图、权限模型、发布手册）

---

## 6. 里程碑与验收（对应 6 个月路线）

- M1：原型（静态页面）
- M2：单体 SPA 可用（Mock 数据）
- M3：工程化与质量护栏
- M4：RBAC + IAM 域闭环
- M5：微前端域拆分（Shell + IAM + Ticket）
- M6：Next.js 帮助中心 + 交付包完善 + 录屏演示
